1. SUMMARY OF IMPLEMENTATION
--------------------------------------------------------------------------------
A bounded, rolling speed history buffer was implemented for download tasks in the
Gopeed Flutter client. This internal data structure maintains historical download
speed samples for active tasks so future chart widgets can render live
speed-over-time graphs.

Key Characteristics:
- Data Structure: `speedHistory` (`RxMap<String, List<double>>`), an observable
  map keyed by task ID with in-memory rolling list of speed values.
- Capacity: Capped at a maximum of 60 samples per task (FIFO: oldest sample dropped
  when cap is exceeded).
- Integrated Lifecycle: Hooks directly into the existing `TaskListController`
  progress update path (`getTasksState()`), avoiding duplicate timers or polling loops.
- Terminal State Handling: Updates stop appending new samples once a task reaches
  a terminal state (`Status.done` or `Status.error`), preserving last recorded history.
- Cleanup: Automatically clears and removes speed history buffers when tasks are
  deleted or omitted from the active task list, plus provides a helper method
  `clearSpeedHistory([String? taskId])` for programmatic resets.
- Zero UI/Behavioral Impact: No UI layouts, widgets, styles, or existing displayed
  speed labels/ETA metrics were modified.
